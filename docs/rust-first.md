# Rust-first runtime and release

The project keeps Python for NeMo reference/export and locked dataset materialization, while deployment inference, CTC decoding, metrics, evaluation artifact generation, and distributable binaries are implemented in Rust.

## Boundary

```text
Python/NeMo export + reference
        |
        v
candidate/model.onnx + metadata.json + vocabulary.json
        |
        v
Rust asr-audio -> asr-runtime -> asr-eval -> JSON contracts
```

The Rust evaluator consumes a resolved/materialized manifest generated by `scripts/ci/prepare-rust-manifest.py`. This intentionally avoids reproducing Hugging Face `datasets`/Arrow semantics in Rust while keeping the actual inference/evaluation path Rust-first.

## Build

```bash
cargo build --release -p asr-eval --no-default-features --features cpu
```

Platform acceleration builds:

```bash
# Windows
cargo build --release -p asr-eval --no-default-features --features cpu,directml

# macOS
cargo build --release -p asr-eval --no-default-features --features cpu,coreml

# CUDA-capable Linux/Windows build environment
cargo build --release -p asr-eval --no-default-features --features cpu,cuda
```

## Release

Pushing a `v*` tag runs `.github/workflows/rust-release.yml`, builds Linux x86_64, Windows x86_64 (DirectML-capable), and macOS Apple Silicon (CoreML-capable) archives, generates `SHA256SUMS`, and creates/updates a GitHub Release.

The same workflow can be started manually with a release tag input.
